## 目标语义一致性与目标级验收（2026-11-16）

问题：原候选表示“进入 Log”，但局部计划只验证控件存在，因此搜索按钮也能被接受。步骤检查中的文本相等、界面变化只证明动作效果，不能证明完成候选功能。

需求与约束：保留原 Function List 的功能名称及来源，不根据执行结果改写 Goal。读取原 StateCluster 已有的功能—控件映射，将真实候选绑定到唯一、可操作的控件；无法解析映射时不猜测。导航计划只允许点击该控件，其他计划的准备动作限输入，终步必须操作目标控件。错误计划在发送事件前拒绝，允许一次带原因的重新规划，失败不发送动作，所有请求计入预算。

目标级 Oracle 在第一次动作前冻结独立验收合同。首版支持可观察的导航及选项选择：目标控件由未选中变为 selected/checked，且对应点击已经由原 EventLog 确认发送并取得匹配的新页面。页面变化、输入匹配、无关控件选中均不能替代此条件。没有合适规则或证据不全时返回 UNKNOWN；不让模型直接宣布 PASS。页面 selected/checked 属性来自真实设备快照。

步骤评估负责推进计划和确认变量，目标评估负责最终结果。只有全部步骤完成且冻结合同满足，才能把状态更新为 PASS。Trace 保存目标锚点、冻结合同、最终评估及证据引用，能够回查原生事件和页面。不得将“功能已尝试”记录当作成功依据。

验收：先建立错误按钮、伪成功、过期/跨任务证据及真实选中转换的失败用例，再实现并完成回归与独立审查。随后沿用上一轮 TimePlanner 的 APK、MuMu1、模型、保留数据、最多五 Goal、300 秒提前触发协议。随机探索及当前页面可能不同，逐项记录真实 Goal，不能将短跑当作正式一小时对照。至少核对错误计划是否被拦截，目标 PASS 是否具有选中转换证据；不为了得到 PASS 改名目标或放宽条件。

验收结果：188 项回归通过，MAESTRO 语句覆盖率 91%，目标选择与目标 Oracle 模块均为 100%。独立审查发现的兼容层缺锚点放行、同资源名替代控件两处问题已先补 RED 用例再修复。真实运行批次 20261116T033127Z 正常退出，81 条 trace、5 个原生动作、Planner/Oracle 各 5 次模型请求；本轮均为点击，没有 Data 文本模型请求。五个 Goal 分别为进入 Log（UNKNOWN，动作前已选中）、入门（UNKNOWN，无对应目标规则）、打开创建类别教程（UNKNOWN，无对应目标规则）、进入 Control（PASS，同一按钮从未选中变为 selected）、过滤记录（UNKNOWN，仅打开过滤界面）。五条动作证据链及唯一目标 PASS 均已核对原生事件和页面。未发生错误按钮计划，错误计划拦截另由回归用例验证。

## 输入与接管验证

新增 enter:widget，要求目标是已经聚焦的输入控件，生成原 KeyEvent(ENTER)。文本与 Enter 是两个单独事件，每次都重新观察和校验。TimePlanner 的创建类别引导需要输入后 Enter，这类界面只有点击与文本提案时无法保证推进。

独立 ModelAndroidOracle 在发送前提出限定规则，确定性检查器依据设备结果求值。每次真实 Oracle 模型调用计入预算。JSON 接口启用 json_object 返回格式，同时继续执行 schema 校验。

LLMDROID_MAESTRO_CANARY=1 用于真实设备接管连通性验收，进入目标 App 并取得原页面摘要后提前触发一次候选选择。LLMDROID_MAESTRO_CANARY_GOALS 可以设置 1–5 次，默认 1。每次仍从真实候选选目标，达到上限后停止。trace 和 manifest 标记 early_guidance_canary，该批次不进入原低增长实验分母。常规运行保留原 AndroLog 低增长门。

设备回调或证据写入异常记录 UNKNOWN。发送结果不明确时保留 uncertain_write，policy 在下一轮停止本场运行，避免恢复探索后重新提交。原生 StateCluster 合同测试直接验证 FunctionList 字段及其页面映射。
